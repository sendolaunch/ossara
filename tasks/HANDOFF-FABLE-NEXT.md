## 1. What OSSARA is

- **Vanilla ESM JavaScript, built with Vite.** No framework.
- **Live 3D engine = PlayCanvas (~1.77).** `three` is legacy/dead — do NOT extend the dead

  `ui/preview.js` import in `screens.js` is a dead import (never instantiated).

  palette; KayKit's look is in the GEOMETRY, not a tiling texture).

## 4. The Build Lab editor (`?artEdit=1`) — the main authoring tool

An in-game PlayCanvas 3D level editor (`src/view/firstBreachBuildMode.js`, big file). Dev-only.
Everything it does is **cosmetic** (never edits collision/routes/grid; output is the kit JSON).
Features built over the last sessions:

- **Real editor mode:** `?artEdit=1` skips the login, hides the hero, disables game input, and is a
  free-fly no-clip camera. Controls: **WASD** fly, **Space** up / **Alt** down, right/middle-drag
  orbit, scroll zoom. **Left-drag** moves a piece; **hold V + drag** = vertical; **arrows** nudge;
  **Q/R** rotate; **F** snap-to-floor; **hold X/Z** axis-lock; **Shift-click** multi-select;
  **Ctrl+C/V** copy-paste (group); **Ctrl+D** duplicate; **Ctrl+Z/Y** undo/redo; **Del** delete;
  **Esc** deselect; **E** export. A **"⌨ Keys / Controls"** button lists them; a **SIZE W×H×D**
  readout shows the selection's dimensions.
- **Auto-build generators (buttons):** "Wrap raised platform faces (stone)" (foundation faces
  around platform edges), "Tile floor (KayKit stone)" (~208 floor tiles), "Scatter clutter
  (un-square)" (rocks/rubble/barrels along wall bases, off-lane, random angle+jitter, re-rollable).
  Each adds to the current layout, is one-Ctrl+Z undoable, and skips protected/route cells.
- **Export → send Hudson's JSON to you → you bake → CC pushes.** That's the loop to make something
  the LIVE map for players.

## 5. ⚠️ The localStorage vs. bake conflict — READ THIS

The editor **auto-saves to `localStorage["fbBuildSave"]` on every change** and, on load,
**restores from localStorage in preference to the baked kit.** Consequences:

- **Baking new content into `firstBreachKit.js` is HIDDEN from Hudson's editor** if he has a local
  save — the editor loads his localStorage, not the freshly-baked kit. (This is why Fable's
  630-piece bake may not appear in his editor until he clears local.)
- To see the deployed/baked version, use the editor's **"Reset to deployed map"** button (clears
  localStorage + reloads from the kit).
- **Rule of thumb:** add NEW map content via **editor generators** (they merge into the current
  layout, auto-saved). Use **baking** to publish the canonical version for players once Hudson
  exports what he wants. Two paths also exist to generate a kit: the interactive editor buttons,
  and Fable's programmatic `scripts/generateFirstBreachFableKit.mjs`.

## 8. Environment gotchas / hard-won lessons

- **Large-file edits corrupt via the Write/Edit tools** (truncation / NUL bytes). Use **bash
  patcher scripts** instead: write a `.cjs` to the outputs dir that does exact-string
  `String.prototype.replace`/`.split().join()` with a MISS check, run it, then `sed -i 's/\x00//g'`
  + `node --check`. This has been the reliable path all session.
- **OneDrive line-ending phantoms:** some files (e.g. `main.js`) show whole-file CRLF↔LF diffs that
  aren't real changes. Before editing such a file, restore it from origin
  (`git show origin/main:src/main.js > src/main.js`) so your diff is clean and stays LF.
- **NEVER `git add -A`** — OneDrive/LFS phantom binaries. **Stage explicit files only** in every
  close-prompt. Track binaries (`*.png *.glb *.gltf *.mp3 ...`) with Git LFS *before* first add.
- **The mount's own `npm run build` fails** (win32 rollup). Build in a clean `/tmp` copy:
  `rsync -a --delete --exclude node_modules --exclude .git --exclude dist src/ /tmp/ob/src/` then
  `(cd /tmp/ob && npm run build)`. **Tests run fine on the mount.**
- **Vercel MCP is unusable here** (personal scope, no team). Verify a deploy by the bottom-right
  version badge SHA (`OSSARA · <sha>`) matching the pushed commit.
- **Verify the live site with the Chrome MCP** (load via ToolSearch): `navigate` to the art link,
  then `javascript_tool` — `window.OSSARA` exposes `flow / hub / mission / startMission`; count
  `build-*` scene entities for the kit; read the badge. The live page can be flaky to screenshot
  under combat (it won't reach `document_idle`) — inspect via JS instead, or screenshot in the prep
  phase. Remember the live editor shows Hudson's **localStorage**, not necessarily the baked kit.
